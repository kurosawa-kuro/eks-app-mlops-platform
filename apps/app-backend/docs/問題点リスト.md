# Hono プロジェクト 問題点リスト

## 1. セキュリティ関連の問題

### 1.1 パスワードハッシュ化の欠如
**場所**: `src/repositories/InMemoryUserRepository.ts`
- **問題**: パスワードが平文で保存・比較されている
- **影響**: 重大なセキュリティリスク
- **推奨対応**: bcrypt や argon2 を使用したパスワードハッシュ化の実装
- **コード箇所**: 12行目（`passwordHash: 'password'`）、35行目（平文比較）

### 1.2 JWT_SECRET のデフォルト値が脆弱
**場所**: `src/config/env.ts`
- **問題**: デフォルト値が `'dummy-jwt-secret-for-dev'` で固定されている
- **影響**: 本番環境で使用された場合、トークンが容易に偽造可能
- **推奨対応**: 
  - デフォルト値を削除し、必須環境変数とする
  - 本番環境では強力なランダムシークレットを必須化
- **コード箇所**: 8行目

### 1.3 入力バリデーションの欠如
**場所**: `src/routes/auth.ts`
- **問題**: ログインエンドポイントでリクエストボディのバリデーションがない
- **影響**: 不正なデータやSQLインジェクション等のリスク
- **推奨対応**: Zod スキーマを使用した入力バリデーションの実装
- **コード箇所**: 6-10行目

### 1.4 レート制限の欠如
**場所**: 全エンドポイント
- **問題**: ブルートフォース攻撃やDoS攻撃に対する保護がない
- **影響**: アカウント乗っ取りやサービス停止のリスク
- **推奨対応**: レート制限ミドルウェアの実装（例: `@hono/rate-limiter`）

### 1.5 CORS設定の欠如
**場所**: `src/app.ts`
- **問題**: CORS設定が実装されていない
- **影響**: クロスオリジンリクエストが制御できない
- **推奨対応**: `@hono/cors` を使用した適切なCORS設定

### 1.6 環境変数の露出
**場所**: `src/views/index.eta`
- **問題**: 環境変数（DATABASE_URL, MONGODB_URI）がフロントエンドに表示されている
- **影響**: 機密情報の漏洩リスク
- **推奨対応**: 機密情報は表示しない、またはマスクする
- **コード箇所**: 46-51行目

## 2. アーキテクチャ関連の問題

### 2.1 未使用の依存パッケージ
**場所**: `package.json`
- **問題**: `drizzle-orm` が依存関係に含まれているが、実際には使用されていない
- **影響**: 不要な依存関係によるバンドルサイズの増加
- **推奨対応**: 
  - 使用する場合は実装を追加
  - 使用しない場合は削除
- **コード箇所**: `package.json` の dependencies（確認が必要）

### 2.2 データベース実装リポジトリの欠如
**場所**: `src/repositories/`
- **問題**: `InMemoryUserRepository` のみで、実際のデータベース実装がない
- **影響**: 本番環境で使用できない
- **推奨対応**: PostgreSQL/MongoDB を使用したリポジトリ実装の追加

### 2.3 データベース接続の非効率性
**場所**: `src/adapters/database/PostgresAdapter.ts`, `src/adapters/database/MongoAdapter.ts`
- **問題**: 接続テストのたびに新しい接続を作成している
- **影響**: パフォーマンスの低下、接続プールの未活用
- **推奨対応**: 接続プールの実装と再利用

### 2.4 エラーハンドリングの不統一
**場所**: 各サービス・ルート
- **問題**: エラーハンドリングの方法が統一されていない
- **影響**: デバッグの困難さ、一貫性の欠如
- **推奨対応**: 統一されたエラーハンドリング戦略の実装

## 3. コード品質関連の問題

### 3.1 型安全性の不足
**場所**: `src/routes/auth.ts`
- **問題**: リクエストボディの型が `any` になっている可能性
- **影響**: 実行時エラーのリスク
- **推奨対応**: 適切な型定義とバリデーション
- **コード箇所**: 8行目（`await c.req.json()`）

### 3.2 エラーメッセージの詳細度不足
**場所**: `src/middleware/errorHandler.ts`
- **問題**: 本番環境で詳細なエラーメッセージが非表示になるが、ログに記録されていない可能性
- **影響**: デバッグの困難さ
- **推奨対応**: エラーログの詳細化と構造化

### 3.3 ハードコードされた値
**場所**: 複数ファイル
- **問題**: マジックナンバーやハードコードされた文字列が存在
- **例**:

  - `src/services/CookieService.ts`: 20行目（`60 * 60`）
- **推奨対応**: 定数ファイルへの抽出

### 3.4 ログレベルの不適切な使用
**場所**: 各サービス
- **問題**: ログレベルの使い分けが不十分
- **影響**: ログの可読性と管理の困難さ
- **推奨対応**: 適切なログレベルの使用ガイドライン
